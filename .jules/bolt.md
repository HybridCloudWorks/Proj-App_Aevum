## 2024-03-20 - Prevent redundant Firestore re-subscriptions
**Learning:** React components subscribing to real-time data sources (like Firestore or WebSockets) often unnecessarily tear down and recreate their subscriptions when arrays or objects are used directly as `useEffect` dependencies.
**Action:** When a subscription requires an ID from an array (e.g., `families[0].id`), extract the specific primitive ID into a variable and use *that primitive* as the `useEffect` dependency, rather than the entire array reference.
## 2024-06-18 - React Subscription Dependencies
**Learning:** In the `apps/web` React codebase, `useEffect` hooks managing Firestore subscriptions often incorrectly include full object references (like `currentFamily`) or state variables (like `user`) in their dependency arrays. This causes redundant re-subscriptions (teardown and setup of network connections) whenever the object reference changes, even if the underlying ID remains the same. Additionally, including the state being set in the same effect (e.g., `setCurrentFamily` needing `currentFamily` in deps) can cause unnecessary re-renders.
**Action:** When managing Firestore subscriptions in `useEffect`, avoid using full array or object references as dependencies. Instead, derive and depend on specific primitive identifiers (e.g., `user?.uid`, `currentFamily?.id`). Use functional state updates (e.g., `setCurrentFamily((prev) => (prev ? prev : data[0]))`) to remove the state variable itself from the dependency array entirely.
